# Практикум ОП01

Распакуйте `OP01-Windows-x64.zip` и запустите `Start.cmd`. В переносимой сборке Python уже включён. При запуске из исходников используется установленный Python. Откроется локальная страница практикума. Консоль с сервером должна оставаться открытой во время работы.

Чтобы обновить локальный практикум, закройте старую копию и распакуйте новый архив в отдельную папку. Скопируйте `progress.sqlite3` из старой папки в новую перед первым запуском. Черновики и результаты сохранятся. Если критерии работы изменились, они применятся при следующей самопроверке.

Оглавление включает все 16 практических занятий из тематического плана ОП01 на страницах 7–12. Вместе они занимают 34 академических часа. Для каждой работы приведены проектные шаги на основе темы. В примере NetLab условия, рабочая область и чек-лист собраны на одном экране. Здесь этот принцип применён к каждой работе отдельно.

Доступны двенадцать работ с Linux-сценариями. В основах соберите паспорт машины, настройте права, выполните задания командной строки, напишите сценарий архивации, пройдите учебную установку Debian и проверьте архив. В администрировании расследуйте сбой службы, освободите место на диске, создайте документ и восстановите контрольный файл из резервной копии. Команда `help` выводит доступные команды работы. Установщик работает с виртуальными учебными данными, а сценарий ClamAV имитирует проверку заранее подготовленных файлов.

В задании на автоматизацию используйте поддерживаемый набор Bash, указанный рядом с редактором. Интерпретатор выполняет его на виртуальных файлах и проверяет сценарий с двумя исходными каталогами и с отсутствующим каталогом.

Симулятор сохраняет состояние машины между занятиями и перезапусками. Стрелки ↑ и ↓ в поле терминала возвращают ранее введённые команды этой работы в открытой вкладке. В работах, где можно менять состояние машины, команда `lab-reset` возвращает его к началу. Черновик и результат последней проверки сохраняются.

Сохраните черновик или выполните самопроверку. Чтобы вернуться к сохранённым ответам и результату, откройте тот же учебный профиль. При обычном открытии практикума в том же браузере сразу откроется последняя работа этого профиля. В редакторе нажмите **«Сохранить файл»**, чтобы сохранить скрипт или заметку после закрытия браузера. Между работами можно переходить через оглавление или кнопки браузера. Несохранённые правки редактора и вывод терминала хранятся в открытой вкладке.

Статус **«В разработке»** означает, что шаги есть в оглавлении и рабочая среда готовится. Статус **«Позже»** относится к Windows-работам. В смешанных темах сначала готовится Linux-часть.

## Первый показ преподавателю

1. Запустите `Start.cmd`. В поле **«Учебный профиль»** введите новое тестовое имя и нажмите **«Открыть»**.
2. Выберите **«Мониторинг и диагностика работы ОС»**. Нажмите **«Проверить работу»** до выполнения действий, чтобы увидеть критерии, которые ещё не выполнены.
3. Введите по одной строке в учебном терминале. Сначала появится `Connection refused`, а после исправления и перезапуска — `HTTP/1.1 200 OK`.

   ```text
   curl -I http://127.0.0.1:8080/health
   systemctl status lab-report.service
   journalctl -u lab-report.service -n 10
   free -h
   sudo sed -i s/PORT=abc/PORT=8080/ /etc/lab-report.conf
   sudo systemctl restart lab-report.service
   curl -I http://127.0.0.1:8080/health
   ```

4. В отчёте выберите причину **«Вместо номера порта в конфигурации записан текст»**, укажите `5` ГиБ доступной памяти и снова нажмите **«Проверить работу»**. Все шесть критериев должны быть зачтены.
5. Откройте **«Сводка преподавателя»** и выберите тестовый профиль. В строке работы появятся **«Пройдена»**, **6 / 6** и **2** попытки. Результат сохранится после повторного запуска `Start.cmd`.

## Задания преподавателя

1. Откройте **«Редактор заданий» → «Новая работа»**. Укажите название, число часов, учебную среду и шаги. На каждый шаг отведите отдельную строку.
2. Отметьте, какие действия и ответы из выбранной среды нужно проверить. В разделе **«Свои вопросы»** можно добавить короткие вопросы с эталонными ответами. При сравнении регистр и лишние пробелы не учитываются.
3. Нажмите **«Сохранить работу»**. После открытия или обновления практикума ученик увидит её в разделе **«Задания преподавателя»**. Результат появится в сводке после выполнения.
4. Чтобы перенести работу на флешке, откройте её в редакторе и нажмите **«Скачать JSON»**. На другом компьютере откройте редактор, нажмите **«Импорт JSON»**, выберите файл, проверьте условие и нажмите **«Сохранить работу»**. Для независимой копии существующей работы используйте **«Создать копию»**.

В локальном режиме редактор открыт на этом компьютере. В режиме класса создание, импорт и эталонные ответы доступны учётной записи преподавателя. В JSON есть эталонные ответы, поэтому ученик открывает работу из оглавления.

### Пример файла и задание через GPT

Импортируйте [example-task.json](example-task.json). В редакторе также есть кнопка **«Скачать пример задания»**. Чтобы попробовать работу, выполните команды из раздела «Первый показ преподавателю». В отчёте выберите причину сбоя и введите `HTTP` в ответ на свой вопрос. Ожидаемый результат — шесть зачтённых критериев.

Для нового варианта можно приложить этот файл к запросу в GPT и написать:

> Сделай новое задание по диагностике учебной службы для ОП.01. Верни один объект JSON в формате приложенного примера, без текста вокруг. Оставь `version: 1`, `template` и коды нужных проверок из `checks`. Замени `id` на новый, сохрани префикс `custom-`, используй минимум восемь строчных латинских букв, цифр или дефисов после префикса. Напиши своё название, шаги и короткие вопросы с ожидаемыми ответами. Каждый шаг должен быть отдельной строкой в массиве `steps`.

Сохраните ответ в файл `.json` в UTF-8 и откройте через **«Импорт JSON»**. Состав доступных проверок зависит от выбранной среды. Чтобы взять другую среду, проще сначала создать работу в редакторе и использовать её экспорт как образец. Ученик выполняет команды и пишет учебные скрипты в рамках возможностей выбранного симулятора.

## Прогресс в компьютерном классе

Нажмите **«Сводка преподавателя»**. Выберите работу, чтобы увидеть, сколько учеников её не начали, сколько ещё выполняют и сколько прошли. Таблицу можно уточнить по профилю и статусу. Для каждой записи видны число зачтённых критериев и число попыток. Кнопка **«Скачать полную сводку CSV»** выгружает данные по всем профилям и работам.

- **Один компьютер для показа или самостоятельной работы.** Запустите `Start.cmd`. SQLite сохраняет прогресс в папке практикума по имени профиля. Сводка показывает данные из этой локальной копии.
- **Несколько компьютеров и одна сводка класса.** Администратор запускает один сервер с учётными записями и PostgreSQL. Ученик может продолжить работу с другого ПК под тем же логином. Администратор может обслуживать PostgreSQL через pgAdmin, преподаватель открывает сводку прямо в практикуме.

### Проверка входа для класса

Создайте учётные записи. Скрипт попросит пароль и запишет в список его хеш. Ученикам сообщается только их собственный пароль. Храните `roster.json` на сервере приложения.

```powershell
python roster.py roster.json pupil1 student
python roster.py roster.json teacher teacher
python -B server.py --roster roster.json --open-browser
```

В этом режиме каждое сохранение привязано к вошедшей учётной записи. Сводка и CSV доступны с ролью `teacher` и показывают только учеников из этого списка. После добавления или смены пароля перезапустите сервер. Перезапуск завершает сеансы входа, сохранённый прогресс остаётся в базе.

В переносимой сборке эти команды можно выполнить через `runtime\python.exe`. Обычный запуск через `Start.cmd` открывает демонстрационный режим SQLite.

### Проверка PostgreSQL

Эта настройка относится к запуску из исходников с установленным Python. Ниже PostgreSQL и практикум работают на одном сервере Windows. В pgAdmin подключитесь к PostgreSQL с учётной записью администратора.

1. В дереве сервера откройте **Login/Group Roles → Create → Login/Group Role**. На вкладке **General** задайте имя `op01_app`, на **Definition** задайте отдельный пароль, на **Privileges** включите **Can login?**. Права суперпользователя для этой роли не нужны. [Настройка роли в pgAdmin](https://www.pgadmin.org/docs/pgadmin4/latest/role_dialog.html)
2. Откройте **Databases → Create → Database**. Укажите имя `op01` и владельца `op01_app`. Приложение создаст свои таблицы при первом запуске.
3. Под учётной записью Windows, из которой будет запускаться сервер практикума, сохраните строку `127.0.0.1:5432:op01:op01_app:ПАРОЛЬ` в `%APPDATA%\postgresql\pgpass.conf`. Подставьте пароль роли и закройте доступ к файлу для остальных пользователей. Если пароль содержит `:` или `\`, экранируйте этот символ обратной косой чертой. [Формат файла паролей PostgreSQL](https://www.postgresql.org/docs/current/libpq-pgpass.html)
4. Из папки практикума установите драйвер и запустите сервер.

```powershell
python -m pip install -r requirements-postgres.txt
$env:OP01_POSTGRES_DSN = 'host=127.0.0.1 port=5432 dbname=op01 user=op01_app'
python -B server.py --roster roster.json --open-browser
```

После тестового сохранения в pgAdmin обновите список **op01 → Schemas → public → Tables**. Появятся `progress` с результатами и `machines` с состоянием учебной среды. В PostgreSQL с изменёнными правами схемы `public` проверьте, что у `op01_app` есть в этой схеме `USAGE` и `CREATE`.

Без переменной `OP01_POSTGRES_DSN` приложение открывает локальную SQLite. Локальные результаты остаются в этом файле при переключении на PostgreSQL.

### Перенос результатов из SQLite

Возьмите файл `progress.sqlite3` с ученического компьютера. При копировании файла сначала закройте локальный практикум. На сервере укажите `OP01_POSTGRES_DSN` и проверьте перенос из исходников приложения с установленным драйвером PostgreSQL.

```powershell
python migrate_progress.py C:\Transfer\progress.sqlite3 --roster roster.json
python migrate_progress.py C:\Transfer\progress.sqlite3 --roster roster.json --apply
```

Первый запуск покажет число новых и уже существующих работ. Второй перенесёт черновики, результаты, число попыток и состояние учебной машины. Вместе с прогрессом переносятся определения выполненных или начатых заданий преподавателя. Если в PostgreSQL уже есть тот же идентификатор задания с другим содержимым, перенос остановится. Если в PostgreSQL уже есть прогресс или состояние по той же работе и учётной записи, перенос пропускает её целиком.

Если на локальном ПК использовали имя `Ученик`, а в классе у него логин `pupil1`, добавьте к обеим командам `--profile "Ученик" --login pupil1`. Повторите перенос для каждой локальной базы. Исходный файл открывается для чтения.

Чтобы проверить вход вместе с PostgreSQL, запустите сервер с переменной `OP01_POSTGRES_DSN` и аргументом `--roster roster.json`.

Локальный адрес приложения — `127.0.0.1`. Для доступа с других рабочих мест используйте утверждённый HTTPS-адрес сервера класса с обратным прокси до этого локального порта. Браузеры обращаются к приложению, а приложение — к PostgreSQL. Для просмотра таблиц и обслуживания базы можно применять pgAdmin.

### Доступ с рабочих мест

`Caddyfile.example` показывает, как подключить [Caddy](https://caddyserver.com/docs/quick-starts/reverse-proxy) на сервере класса. Администратору понадобятся имя сервера в сети класса, его IP-адрес и PEM-сертификат для этого имени, цепочке которого доверяют браузеры рабочих мест. Caddy устанавливается отдельно.

В первом окне PowerShell запустите `python -B server.py --roster roster.json` с настроенной `OP01_POSTGRES_DSN`. Во втором окне укажите параметры прокси. Замените примеры на значения, выданные администратором.

```powershell
$env:OP01_CLASSROOM_HOST = 'op01.school.example'
$env:OP01_BIND_ADDRESS = '192.0.2.10'
$env:OP01_TLS_CERT = 'C:/OP01/tls/fullchain.pem'
$env:OP01_TLS_KEY = 'C:/OP01/tls/privkey.pem'
caddy validate --config Caddyfile.example --adapter caddyfile
caddy run --config Caddyfile.example --adapter caddyfile
```

Если сервер приложения запущен с `--port`, задайте тот же порт в `OP01_APP_PORT`. По умолчанию это `8174`. Ученики и преподаватель открывают в браузере один HTTPS-адрес и входят со своими учётными записями. Для браузеров из сети класса достаточно доступа к HTTPS-порту прокси.
